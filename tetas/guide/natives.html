Calling natives ​

Game and server functions, exposed as a huge static class Native of strongly-typed methods. No more Function.Call<T>(Hash.X, …).

Client nativesCitizenFX.FiveM.Client.dll~7,600 methods — the full GTA V native surface. Browse the reference →
Server nativesCitizenFX.FiveM.Server.dll~379 methods — the server-authoritative subset. Browse the reference →

The full reference lives on this site

Every native is documented, organized by game namespace, in Client natives and Server natives — with signatures, parameter tables, hashes and descriptions from the community database. Use the search box; it indexes them all.

The generated shape ​

Each native is a thin, generated wrapper over the invocation contract: reset, push, invoke by hash, read result.

csharp
// decompiled native
public static string GetResourceState(string name)
{
    Native.nativeApi.ResetContext();
    Native.nativeApi.PushArg<string>(name);
    Native.nativeApi.Invoke(1077523589UL, nameof(GetResourceState));  // native hash
    return Native.nativeApi.GetResString(0).ToString();
}

You just call it:

csharp
using CitizenFX.FiveM.Server;      // NOTE: on the client, Native also lives here (see below)

string state = Native.GetResourceState("chat");
Vector3 pos  = Native.GetEntityCoords(entity, true);
int type     = Native.GetEntityType(handle);   // 1 ped · 2 vehicle · 3 object

Namespace quirk (client)

On the client, the Native class is compiled under the CitizenFX.FiveM.Server namespace (the file lives at Client/FiveM/Server/Native.cs). So client code writes using CitizenFX.FiveM.Server; to reach natives. It's expected — not a mistake.

Output parameters ​

Natives with out-values are surfaced two ways: a real C# out overload and a Ref<T> overload. Both are backed by the same result-index read (often located via a shifted return value, e.g. Invoke(...) >> 6).

csharp
// out overload — idiomatic:
int result = Native.GetVehicleInteriorColour(veh, out int colour);

// Ref<T> overload — a ref struct wrapping `ref T Value`:
var colour = new Ref<int>(0);
Native.GetVehicleInteriorColour(veh, colour);
int c = colour.Value;
csharp
// CitizenFX.FiveM.Shared.Data.Ref<T>
public ref struct Ref<T>(ref T val)
{
    public readonly ref T Value = ref val;
}

Result types ​

Return values map to ordinary CLR types through the typed getters on the bridge:

Native returnsBridge getterC# type
int / handle / enumGetResIntint
floatGetResFloatfloat
boolGetResBoolbool
stringGetResStringstring (via StringRes)
vector3GetResVectorSystem.Numerics.Vector3
object / structGetResObjectConstBuffer → MessagePack

Hashes

Native hashes are baked into each method as a ulong literal, so you don't pass them. For string→hash conversions (models, etc.) use API.Hash("key"), the Joaat hash.

Prefer entity wrappers where they exist ​

For common entity operations, the entity wrappers already call the right natives behind clean properties — e.g. vehicle.Position, ped.Health, player.Name. Drop down to raw Native.* for anything the wrappers don't cover.

csharp
// wrapper (client):
Vehicle v = API.Vehicles.GetOrCreate(handle);
v.Position = new Vector3(0, 0, 72);

// equivalent raw native:
Native.SetEntityCoords(handle, 0f, 0f, 72f, true, false, false, false);
