Gotchas & quirks ​

The sharp edges found while reading this build. Some are bugs, some are just surprising.

Client Side reports Server

CitizenFX.FiveM.Client.Core.Side returns Side.Server — identical to the server side — which looks like a copy/paste bug in this decompiled build. Don't branch client-vs-server logic on SharedAPI.Side here. Split by assembly / by which side's script you're writing instead.

Version lock-step

BaseEntrypoint.GetParameterAs throws "Failed to find initialization parameter … Make sure your NuGet version matches server version" when an expected init key is missing. Compile against the exact runtime version your server ships, and never bundle your own copies of the CitizenFX.* / MessagePack assemblies (<Private>false</Private>).

Core APIs are internal (FIVEM001)

Members reached via API.GetCore() / SharedAPI.GetCore() carry [Obsolete(... DiagnosticId = "FIVEM001")] — "intended only for internal usage and might be modified or removed without warning." Stick to the static API / SharedAPI facades; treat anything on Core as unstable.

Main-thread discipline

Emitting events and calling natives off the main thread throws "This function has to be called from the main thread only." Background work must marshal back with RunOnMainThread / await JumpToMainThread() before touching the game. See Threading.

Client's Native lives in the ...Server namespace

On the client, the Native class is compiled under CitizenFX.FiveM.Server (the file is at Client/FiveM/Server/Native.cs). Client code writes using CitizenFX.FiveM.Server; to call natives. Expected, not a bug.

Networked events silently ignore [OnEvent]

Only handlers with AllowNetwork (i.e. [OnNetEvent]) receive events whose source is net:*. A plain [OnEvent] on a networked event won't fire and won't warn. See Events.

Composite-format logging, not interpolation

The Log.X(format, args) overloads use string.Format with {0}-style placeholders. API.Log.Info("x = {0}", x) is correct; passing an already-interpolated string with a stray { can throw a format exception. Use the single-string overload for interpolated messages.

Unhandled exceptions can be fatal

A background exception that escapes to AppDomain.UnhandledException is routed to the host's CriticalFailure. Handler invocations are already wrapped by the managers; your own detached tasks/threads are not — guard them (or return Task so the wrapper logs faults).

Scripts need a public parameterless ctor

Discovery uses Activator.CreateInstance(type). A class with only a parameterized constructor won't instantiate and will silently not load. Keep an implicit or explicit parameterless constructor.

Command argument errors are swallowed to the log

If a caller passes an unparseable value, the command handler logs an error and does nothing — the player sees no feedback. Prefer nullable/defaulted parameters, or take [FromRawCommand] string and validate yourself. See Commands.

That's the tour. If a name or behaviour here doesn't match your server's assemblies, trust the assemblies — this reference tracks one decompiled build (net10test, v1.0.0.0) and the runtime is young.
