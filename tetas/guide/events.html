Events ​

The backbone of the runtime. Three axes: local vs networked, who emits, and declarative ([OnEvent]) vs imperative (API.OnEvent).

Receiving events ​

csharp
// Declarative — auto-registered from the attribute (see Scripts & lifecycle):
[OnEvent("onResourceStart")]                 // local only
private void OnResStart(string resourceName) { }

[OnNetEvent("shop:buy")]                      // networked (AllowNetwork = true)
private void OnBuy([FromSource] ISharedPlayer buyer, int itemId, int qty) { }

// Imperative — register at runtime; returns an int handler id:
int id = API.OnEvent("tick:custom", new Action(() => { /* ... */ }));
int nid = API.OnNetEvent("chat:msg", new Action<string>(msg => { /* ... */ }));

Networked events require [OnNetEvent]

A plain [OnEvent] will silently not fire for events arriving over the network. When the source is net:*, the dispatcher only calls handlers whose AllowNetwork flag is set. Use [OnNetEvent] (or API.OnNetEvent, or allowNetwork: true).

Registering any handler also calls Native.RegisterResourceAsEventHandler(eventName) under the hood, so the host knows to route that event name to your resource.

Emitting events ​

CallSideGoes to
API.EmitLocal(name, args)bothThe local event bus (this side, all resources).
API.EmitServer(name, args)clientThe server.
API.EmitServerLatent(bps, name, args)clientThe server, rate-limited to bps bytes/sec.
API.EmitClient(target, name, args)serverOne client (target = server id; -1 = all).
API.EmitClientLatent(target, bps, name, args)serverOne client, rate-limited.
csharp
// client → server
API.EmitServer("myresource:ping", playerName, amount);

// server → one client
API.EmitClient(serverId, "myresource:notify", "Welcome!");

// server → all clients
API.EmitClient(-1, "myresource:announce", "Server restart in 5m");

// same side, cross-resource
API.EmitLocal("myresource:internal", payload);

Arguments are MessagePack-serialized — with SerializerOptions for local emits and RemoteSerializerOptions for networked ones (the remote profile encodes entities as network ids; see Serialization). All emit paths call TickManager.AssertMainThread() first, so emitting off-thread throws.

Source & [FromSource] ​

Networked events arrive with a source string, decoded as type:handle. For a "net:3" source, the numeric handle 3 is exposed as Source and the whole string as SourceString. A [FromSource] parameter reads exactly that:

csharp
[OnNetEvent("bank:withdraw")]
private void Withdraw(
    [FromSource] ISharedPlayer player,   // resolved from Players.Get(source)
    int amount) { }

// Same handler, different source shapes:
[OnNetEvent("bank:withdraw")]
private void Withdraw2([FromSource] int serverId, int amount) { }   // numeric

[OnNetEvent("bank:withdraw")]
private void Withdraw3([FromSource] string src, int amount) { }     // "net:3"

Source decoding

The dispatcher parses the source as type:handle when it contains :; a bare integer becomes the handle with an empty type; anything else is kept as the type with handle 0. The net type is what marks an event as "networked" for the AllowNetwork filter.

One-shot & removal ​

csharp
// fire exactly once, then auto-remove:
API.OnEvent("game:ready", new Action(() => Boot()), once: true);

// remove one handler by id, or every handler for an event:
int id = API.OnEvent("tick:custom", handler);
API.OffEvent("tick:custom", id);     // remove that one
API.OffEvent("tick:custom");         // remove all handlers for the event

Under the hood each registration stores an EventHandler record (Callback, AllowNetwork, HandlerName, HandlerId, Once). After a dispatch, if any invoked handler was Once, the dispatcher removes the spent one-shots (respecting the network/local split).

Error handling ​

Handler invocation is wrapped. A bad-argument exception and a general exception are reported differently, and neither takes down the dispatch loop:

InvalidWrappedCallArgException → Log.Warn Raised when an argument can't be deserialized to the parameter type, or a required non-nullable arg is missing/null. The warning includes the handler name, source, and the JSON of the offending args.

Any other Exception → Log.Error Logged with handler, source, args-as-JSON, and the full exception. Other handlers for the same event still run.

Async event handlers

Returning Task is supported and recommended for I/O — the wrapper attaches a continuation that logs faults, so you don't need a top-level try/catch just to avoid crashing.

Dispatch internals ​

The host calls back into Entrypoint.OnEvent(name, source, args), which forwards to SharedEventManager.InvokeOwnedEvent:

InvokeOwnedEvent(name, source, argsBytes)
  • (type, handle) = DecodeSource(source)
  • look up handlers for name; if none, return
  • isNet = type == "net"
  • CallParams par = new(argsBytes,
        isNet ? RemoteSerializerOptions : SerializerOptions) { Source = handle, SourceString = source }
  • for each handler (net → only AllowNetwork ones):
        try handler.Callback(ref par)
        catch InvalidWrappedCallArgException → Log.Warn
        catch Exception                      → Log.Error
  • remove spent once-handlers
